# BINARIES_SETUP — Native binaries for the Pixie Dust module

The Pixie Dust module in AmWF requires several binaries compiled for Android ARM.
Both ABIs are packaged: `arm64-v8a` (the modern ARM64 architecture used by current
Snapdragon devices) and `armeabi-v7a` (older 32-bit devices).

## Current assets layout

```
app/src/main/assets/wifi/
├── pixiewps                # arm64-v8a   ✅ built with NDK r27
├── pixiewps_32             # armeabi-v7a ✅ built with NDK r27
├── wpa_supplicant          # arm64-v8a   ✅ own wpa_supplicant 2.11
├── wpa_supplicant_32       # armeabi-v7a ❌ intentionally not shipped (32-bit unsupported)
├── wpa_cli                 # arm64-v8a   ✅ built from wpa_supplicant 2.11
├── wpa_cli_32              # armeabi-v7a ♻️ preserved prebuilt asset (the script does not regenerate it)
├── wpa_supplicant.conf     # base supplicant configuration
├── libnl-3.so.200          # arm64-v8a   ✅ libnl 3.2.25
└── libnl-genl-3.so.200     # arm64-v8a   ✅ libnl 3.2.25 (genl)
```

On 32-bit devices `NativeBinaries.archSuffix()` resolves to `"_32"`, and
`missingCriticalBinaries()` therefore reports the missing `wpa_supplicant_32`; the
audit stops with a clear message. The packaged supplicant is only built for
arm64-v8a.

## 1. Why an own wpa_supplicant

Android's `wpa_supplicant` is built with `CONFIG_ANDROID_LOG`. In that variant
`_wpa_hexdump()` truncates dumps to **32 bytes** and sends them to logcat. Pixie
Dust needs the six complete M3 fields, including the **192-byte** DH public key
(384 hex characters), so the truncated dump is useless.

AmWF's binary is built **without** `CONFIG_ANDROID_LOG` and **with**
`CONFIG_DEBUG_FILE=y`. Without `-f`, debug output (including the complete
hexdumps) goes to **stdout**, which is exactly what `M3Parser` reads. That is why
`NativeBinaries.missingCriticalBinaries()` does **not** accept the system
`wpa_supplicant` as a substitute: even if present, it cannot deliver the complete
DH keys. The format is:

```
WPS: Enrollee Nonce - hexdump(len=16): 01 02 ...
WPS: DH own Public Key - hexdump(len=192): ...
WPS: DH peer Public Key - hexdump(len=192): ...
WPS: AuthKey - hexdump(len=32): ...
WPS: E-Hash1 - hexdump(len=32): ...
WPS: E-Hash2 - hexdump(len=32): ...
```

`-K` is required so `wpa_hexdump_key()` prints `AuthKey` instead of `[REMOVED]`.

The supplicant also ships `scripts/patches/wpa_supplicant-2.11-stdout-flush.patch`,
which adds an `fflush(stdout)` after each debug line so the M3 fields are
parseable as they are emitted instead of after process exit. See
`THIRD-PARTY-NOTICES.md` for the full provenance.

**Fallback to system binaries (`wpa_cli` and `pixiewps`).** Unlike the supplicant,
`wpa_cli` and `pixiewps` *can* be resolved from the system when the packaged asset
is unavailable: `resolveBinaryPath()` looks first in `filesDir` (where `ensure()`
copies the assets) and then in `/system/bin`, `/vendor/bin`, `/vendor/bin/hw`,
`/system/xbin` and `/odm/bin`, using the name without the architecture suffix. If a
binary is not found anywhere, it is reported as missing as usual. The fallback is
intentional: `wpa_cli` only passes text commands to the supplicant and `pixiewps`
works offline on already-captured data; neither touches the WPS hexdump. The system
`wpa_supplicant` stays excluded from this fallback for the reason explained above.
Visible consequence: the **Pixie Dust Binaries** row may show as available even when
the packaged `wpa_cli` or `pixiewps` asset is missing, because the system copy is
being used.

## 2. Reproducible build

`scripts/build-wifi-binaries.sh` builds the binaries for **arm64-v8a**
(pixiewps, wpa_supplicant, wpa_cli and libnl). For **armeabi-v7a** it only builds
`pixiewps_32`: the 32-bit supplicant is unsupported and `wpa_cli_32` is kept as a
prebuilt asset, never regenerated by the script. It requires the sources:

```
../pixiewps-master/
../wpa_supplicant-2.11/
../libnl-3.2.25/
```

and NDK r27 (or later):

```bash
export ANDROID_NDK=/opt/android-sdk/ndk/27.0.12077973
./scripts/build-wifi-binaries.sh arm64-v8a
```

Steps performed for the supplicant:

1. Builds **libnl 3.2.25** for Android with `--disable-static --enable-shared`.
   Applies `scripts/patches/libnl-3.2.25-wpa2.11.patch`, which adds `NLA_S8` and
   `nla_get_s8()` (wpa_supplicant 2.11 uses them and libnl 3.2.25 did not have
   them yet). The linker scripts `libpthread.so`/`librt.so` point at `libc`, because
   bionic integrates pthread/rt and the NDK sysroot does not provide those `-l`
   names.
2. Copies `defconfig` to `.config` and disables DBus, syslog, AP, P2P, DPP, SAE,
   EAP-PWD, wired/macsec/wext drivers and other features a WPS station does not
   need. Enables internal TLS, libtommath, `CONFIG_NO_RANDOM_POOL`,
   `CONFIG_DEBUG_FILE`, WPS, nl80211 and libnl32.
3. Adds a filtered include directory (`build-include/netlink`) so libnl's old copy
   of `<linux/if.h>` does not shadow bionic's. Otherwise the compiler sees an
   incomplete `struct ifreq`.
4. Creates `private/android_filesystem_config.h` with the AIDs used by
   `wpa_ctrl.c` and `os_unix.c`.
5. Builds `wpa_supplicant` and `wpa_cli` with API 24, strips them and copies them
   into `assets/wifi/`.

## 3. Runtime: libraries and LD_LIBRARY_PATH

`SupplicantProcesses` exports `LD_LIBRARY_PATH=<filesDir>` in the command that
launches `wpa_supplicant`, so the dynamic linker finds `libnl-3.so.200` and
`libnl-genl-3.so.200` in the same directory. `libc.so`, `liblog.so`, `libm.so`,
`libdl.so` and the rest of bionic come from the device itself and are not packaged.

`wpa_cli` only links against bionic; it does not need libnl.

## 4. wpa_supplicant.conf

The asset contains the base configuration:

```
ctrl_interface_group=wifi
update_config=1
ap_scan=1
```

`SupplicantProcesses.stageConfig()` (invoked by the runner) drops the
`ctrl_interface*` lines and generates a runtime config with the real socket path:

```
ctrl_interface=DIR=/data/vendor/wifi/amwf GROUP=wifi
update_config=1
ap_scan=1
```

The config is sent through `su`'s stdin because the `su` SELinux domain cannot
read `filesDir`. `update_config=1` lets `save_config` persist the PSK after WPS
provisioning.

## 5. Permissions and SELinux

- The app runs the binaries via `su`. The device must be rooted.
- The control directory is `/data/vendor/wifi/amwf` on Android 9+ (API 28+, the
  path granted in the mainline SELinux policy for devices launched with P or
  later, and the only one in force on Android 10+). On older versions (or devices
  that *upgraded* to P instead of launching with it, which keep the legacy path)
  the code uses `/data/misc/wifi/amwf` (`SDK_INT < 28`). The distinction depends on
  what the device launched with, not only on the reported version; if the
  supplicant fails with "socket not created", try the other directory.
- The control directory is created and labelled with the `su` process context;
  the socket is created as long as the config declares `ctrl_interface`. If an
  attack fails with "socket not created", review the command and the runtime
  config before blaming SELinux.
- Do not delete `/data/vendor/wifi/wpa/sockets`; it belongs to the system supplicant.

## 6. Verification

Install the app on a rooted device, check **Device Compatibility** (the **Pixie
Dust Binaries** row) and launch **WPS Pixie Dust Audit**. The app log must show
`wpa_supplicant ctrl interface ready (PONG)` and, after `wps_reg`, the six complete
`WPS: ... - hexdump(len=...)` lines.
